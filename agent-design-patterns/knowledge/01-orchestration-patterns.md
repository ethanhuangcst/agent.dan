# 编排类模式：Prompt Chaining、Routing、Parallelization、Tool Use

来源：《Agentic Design Patterns》第 1、2、3、5 章。这四个模式解决同一个问题：把一次不可靠的大提示，拆成受控的执行结构。

来源：https://github.com/DanieleSalatti/AgenticDesignPatterns

## Prompt Chaining（第 1 章）

定义：把复杂任务分解为顺序子问题序列，每步用一个专门设计的提示词处理，上一步输出作为下一步输入，形成依赖链。

适用条件：任务可分解为固定顺序步骤，如"摘要 → 提取趋势 → 撰写邮件"三段式市场分析流水线。步骤间用 JSON 等结构化格式传递数据，是链式可靠性的关键。

不适用条件（推断）：步骤间无依赖时应改用并行；需要动态分支时应与 Routing 组合；链越长误差累积越大，超过 5-6 步需插入校验点。

书中要点：单提示词处理多约束任务有五种失效——指令被忽略、上下文漂移、误差传播、上下文窗口不足、幻觉放大。

## Routing（第 2 章）

定义：系统先分析输入的意图或性质，再把控制流动态导向最合适的专用工具、函数或子 agent。

适用条件：agent 必须在多个不同工作流之间做选择，如客服机器人区分销售、技术支持、账号管理三类请求。实现方式有三种：LLM 判断、预定义规则、embedding 语义相似度。

不适用条件（推断）：只有一条执行路径时无收益；分流维度少于两个时不值得引入路由开销；规则若能解决，不必用 LLM 判断。

## Parallelization（第 3 章）

定义：识别工作流中互不依赖的子任务，让它们同时执行，总耗时从"各任务之和"降为"最慢任务"。

适用条件：多个独立 I/O 操作，如同时调多个 API、分块处理数据、生成多份待汇总的内容。LLC 中用 RunnableParallel，ADK 中用 coordinator agent 把子任务委派给并行的子 agent。

不适用条件（推断）：任务有严格先后依赖时不可并行；书中明确指出并发会显著增加设计、调试和日志的复杂度与成本，低流量简单任务不值得付这个代价。

## Tool Use / Function Calling（第 5 章）

定义：LLM 根据请求与工具定义，生成结构化调用请求（工具名 + 参数），由编排层执行真实函数并把结果回传给模型，使其能访问实时数据、执行计算、触发真实动作。

适用条件：任何需要超越文本生成的场景——查实时数据、查数据库、发邮件、执行代码、控制设备。六步流程：工具定义 → 模型决策 → 生成调用 → 执行 → 结果回传 → 模型继续处理。

不适用条件（推断）：纯文本生成任务；工具数量激增时模型选错工具的比率上升，需要配合 Routing 收敛候选集。

## 组合要点

- 典型生产结构：Routing 分流 → Chaining 串行主流程 → Parallelization 处理独立取数 → Tool Use 触达外部系统。
- 复杂流程常混合使用：独立取数用并行，依赖步骤用链式，汇总与审校是串行的。
