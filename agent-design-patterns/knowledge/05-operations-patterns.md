# 运维与规模化类模式：MCP、A2A、Resource-Aware Optimization、Reasoning、Evaluation、Prioritization、Exploration

来源：《Agentic Design Patterns》第 10、15、16、17、19、20、21 章。这组模式面向系统集成、成本控制与持续运营。

来源：https://github.com/DanieleSalatti/AgenticDesignPatterns

## Model Context Protocol / MCP（第 10 章）

定义：LLM 与外部系统之间的开放标准协议，客户端-服务器架构，服务器对外暴露工具、数据资源与交互式提示，客户端动态发现并调用。

适用条件：复杂、可扩展或企业级系统需要接入多样且持续演进的外部工具与数据源；优先考虑跨 LLM 与工具的互操作性；要求不重新部署即可发现新能力。

不适用条件（推断）：工具少而固定时直接 function calling 更简单，引入 MCP 只增加一层协议开销。

## Inter-Agent Communication / A2A（第 15 章）

定义：基于 HTTP 的开放协议，让不同框架构建的 agent（ADK、LangGraph、CrewAI 等）互相发现、协调与委派任务。核心组件是 Agent Card——描述 agent 能力、技能与通信端点的数字身份文件。

适用条件：跨框架编排两个以上 agent；模块化架构中各专用 agent 独立部署；需要动态发现其他 agent 能力。支持同步请求、异步轮询与流式更新，内置 mTLS 等安全机制。

不适用条件（推断）：同一框架或同一进程内的 agent 协作，直接调用即可；与 MCP 的分工——MCP 连接模型与外部资源，A2A 管 agent 之间的任务协调。

## Resource-Aware Optimization（第 16 章）

定义：根据实时约束（成本、延迟、算力）动态分配资源：Router Agent 判断请求复杂度，简单查询给快而便宜的模型，复杂推理给强模型；Critique Agent 评估响应质量并反馈改进路由逻辑。

适用条件：API 预算受限、延迟敏感、边缘设备部署、需在质量与成本间程序化权衡的场景。

不适用条件（推断）：流量小或预算宽松时单一模型更简单；书中列出的其他手段包括自适应工具选择、上下文裁剪与摘要、优雅降级与回退。

## Reasoning Techniques（第 17 章）

定义：让推理过程显式的技术：Chain-of-Thought 生成中间推理步骤提升多步推理准确率与可审计性；ReAct 交替推理与行动；配合推理期更多计算资源换取准确率。

适用条件：多跳问答、数学问题、代码调试、战略规划、医疗诊断、法律分析等需要显式分步推理的任务。

不适用条件（推断）：模式化简单问答，显式推理只增加延迟与 token 成本。

## Evaluation and Monitoring（第 19 章）

定义：对运行中的 agent 做持续、通常外部的度量：定义指标、建立反馈回路、实现报告系统，覆盖效果、效率与合规。

适用条件：生产部署的性能追踪（准确率、延迟、解决率）、agent 版本 A/B 测试、合规与安全审计报告。

不适用条件（推断）：尚无生产部署时无运行指标可采；但上线前应先定义好指标，书中主张评估能力是 agent 系统的组成部分而非事后补充。

## Prioritization（第 20 章）

定义：agent 按紧迫性、重要性、依赖关系与资源成本等标准给任务排序，并可随环境变化动态重排。

适用条件：agent 需在冲突目标与有限资源下自主管理多个任务。

不适用条件（推断）：同一时刻只有一个待办任务时排序无意义。

## Exploration and Discovery（第 21 章）

定义：让 agent 主动探索新信息、发现"未知的未知"：多 agent 框架模拟科学方法——生成假设、批判审查、演化最优概念，如 Google Co-Scientist 自动生成假设并设计实验。

适用条件：开放式、解空间未定义的领域：科学研究、市场分析、创意内容生成。

不适用条件（推断）：目标明确的优化型任务不需要探索机制，探索的随机性反而降低效率。

## 组合要点

- 生产系统的运维底线：Evaluation 持续度量 + Resource-Aware 控成本 + MCP/A2A 管集成边界。
- 这组模式的共同前提是"系统已在运行"：设计期应优先落地 01-04 组的模式，再按运营压力逐步引入本组。
